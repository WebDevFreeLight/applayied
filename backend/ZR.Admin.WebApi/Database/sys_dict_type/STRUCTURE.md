## File Categories

### 1. Dictionary Type Definitions (`sys_dict_type/`)
**Purpose**: Define the dictionary types that will be used in the application

**Files**:
- Individual JSON files for each dictionary type
- Combined JSON file with all types
- SQL query reference file
- Documentation

**Usage**:
- Manual import into `sys_dict_type` table
- Reference for understanding the dictionary structure
- Template for adding new dictionary types

### 2. Source Data (`SeedData/EventManagement/`)
**Purpose**: Source data for Event Management entities

**Contains**:
- Raw data for all Event Management tables
- Type definitions (event_types, zone_types, etc.)
- Entity records (events, tickets, permits, etc.)

**Generated By**:
- Manual data entry or Excel import
- Database exports

### 3. Generated Dictionary Data (`SeedData/sys_dict_type/EventManagement/`)
**Purpose**: Auto-generated dictionary data from source tables

**Contains**:
- `sys_dict_type` entries
- `sys_dict_data` entries for each type
- Combined data files

**Generated By**:
- `SeedDataService.GenerateAndSaveAllDictionaries()`
- Runs automatically during seed data initialization

## SQL Query Pattern

All dictionary types follow this pattern (based on HR employee example):

```sql
SELECT
    [primary_key] AS dictValue,
    CONCAT([field1], ' - ', [field2], ' - ', [field3]) AS dictLabel,
    remark
FROM [source_table]
ORDER BY [primary_key];
```

### Examples:

**Event Types:**
```sql
SELECT typecode AS dictValue,
       CONCAT(typecode, ' - ', typename, ' - ', typenamear) AS dictLabel,
       remark
FROM event_types;
```

**HR Employees:**
```sql
SELECT employeeid AS dictValue,
       CONCAT(firstname, ' ', lastname, ' ', namear) AS dictLabel,
       remark
FROM hr_employee;
```

**Event Locations:**
```sql
SELECT locationid AS dictValue,
       CONCAT(locationid, ' - ', locationname, ' - ', city) AS dictLabel,
       address AS remark
FROM event_locations;
```

## Key Features

### 1. Bilingual Support
All labels include both English and Arabic text:
- `typename` (English) + `typenamear` (Arabic)
- Example: "VIP - VIP Guest - ضيف كبار الشخصيات"

### 2. Automatic Updates
When source data changes:
1. Re-run seed data initialization
2. System automatically regenerates dictionary data
3. Updates both JSON files and database

### 3. Flexible Structure
- Individual files for granular control
- Combined files for bulk operations
- SQL files for direct database operations

## Usage Examples

### Import Dictionary Types
```bash
# Import all dictionary types
POST /api/system/seed/initialize

# Or use JSON files directly
psql -d MahamDB -c "COPY sys_dict_type FROM '/path/to/all_event_management_dict_types.json';"
```

### Query Dictionary Data
```csharp
// Get all event types for dropdown
var eventTypes = await _dictDataService
    .GetDictDataByType("event_type");

// Get HR employees for assignment
var employees = await _dictDataService
    .GetDictDataByType("hr_employee");
```

### Add New Dictionary Type

1. Create JSON definition in `sys_dict_type/[new_type].json`
2. Add to `all_event_management_dict_types.json`
3. Add method in `SeedDataService.cs`:
   ```csharp
   public List<SysDictData> GenerateDictDataFrom[NewType]()
   {
       // Query source table
       // Generate dict data entries
       // Return list
   }
   ```
4. Add to `GenerateAndSaveAllDictionaries()` method
5. Re-run seed initialization

## Maintenance

### Adding New Types
1. Follow naming convention: `[entity]_type` or `[module]_[entity]`
2. Update `all_event_management_dict_types.json`
3. Add SQL query to `dictionary_queries.sql`
4. Implement generation method in C#

### Updating Existing Types
1. Modify source data in `SeedData/EventManagement/`
2. Re-run seed initialization
3. Generated files automatically update

### Troubleshooting
- Check logs in seed initialization results
- Verify source tables have data
- Ensure column names match expected pattern
- Check file permissions for JSON output
