# PMO Portal — Interactive Executive Presentation

An immersive, fully offline investment pitch for **PMO Portal — Project Portfolio & Financial Control**, presented to the (fictional) Sahel Holding Group investment committee.

> **To present:** double-click `index.html` (extracting the ZIP first is recommended, but it also works opened straight from inside the ZIP). It is a single self-contained file — styles, scripts and fonts are embedded — and runs in current Chrome or Edge with no server, login, install or internet connection.

All organisations, people and financial figures are **fictional and illustrative**. Delivery records (projects, milestones, monthly snapshots, and most tasks, risks and change requests) mirror the PMO Portal's own demo/seed dataset. The demo account used could only see 5 of the 8 projects, so a few tasks, risks and change requests for NBU, DLP, CYB and AIC were added as illustrative records. Costs, EAC, savings and the business-case model are assumptions made for this pitch.

## Presenter controls

| Key / control | Action |
|---|---|
| `→` `Space` `PgDn` · HUD › | Next scene |
| `←` `PgUp` · HUD ‹ | Previous scene |
| `1`–`9`, `0` · progress bar | Jump to scene 1–10 |
| `Home` / `End` · HUD ⌂ | Opening / final scene |
| `F` · ⛶ | Full screen (Esc exits) |
| `P` · ❚❚ | Pause / resume looping motion |
| `M` · ◐ | Reduced-motion mode (also respects the OS setting) |
| `?` | Shortcut help |

The current scene, simulator inputs and reduced-motion choice are remembered (`localStorage`). The opening scene offers **Resume at scene N**, and `index.html#7` deep-links to a scene. The HUD fades when idle and returns on mouse movement.

**Cross-scene continuity:** the eight project nodes on the background canvas never disappear. They move from an orbit (01) to scattered, red-alarm chaos (02), collapse into the hub (03), line up as a quiet header (04, 07), and finish as a healthy row (08, 10).

**Motion techniques (≥3):** canvas particle/parallax system, SVG path drawing (spokes, wires, roadmap), coordinated WAAPI choreography (converge / zoom / iris transitions), kinetic word masks, packets travelling along SVG paths, keyed SVG geometry that tweens between chart states, and number counters.

## Project structure

```
index.html            BUILT, self-contained presentation (open this) — generated by build.py
build.py              bundles src/ into index.html (inlines CSS, JS and base64 fonts)
src/index.html        scene markup + presenter HUD (edit here)
src/css/styles.css    design tokens, layout per scene, chart marks
src/js/data.js        single source of truth for every number (pilot data + illustrative finance)
src/js/models.js      PURE functions: dashboard KPIs, business-case simulator, automation model
src/js/fx.js          motion primitives + "scope" lifecycle (cancel everything on scene exit)
src/js/charts.js      tiny keyed-SVG chart kit (bars, lines, donut, heatmap, stacked)
src/js/constellation.js  persistent background canvas (cross-scene continuity)
src/js/scenes.js      one object per scene: layout, transition, enter(ctx), persistent state
src/js/controller.js  scene controller: scaling, navigation, transitions, HUD, resume
src/assets/fonts/     Space Grotesk, Inter, JetBrains Mono (woff2, SIL OFL)
pptx/build-deck.js    generates the PowerPoint companion from the SAME data.js / models.js
PMO_Portal_Management_Presentation.pptx   10-slide companion deck with native charts & speaker notes
DEVLOG.md             AI-assisted development log (prompt iterations, corrections, verification)
```

Edit files in `src/`, then run `python build.py` to regenerate `index.html`. `src/index.html` also runs on its own (it links the files beside it) for development.

## How it works (for the technical interview)

**Scene controller (`controller.js → go(i)`)**
1. If a transition is still running, finish it instantly, so there are no stuck half-states when someone clicks quickly.
2. `scope.dispose()` on the outgoing scene cancels its animations, timers, rAF loops and event listeners.
3. Tell the constellation the new layout and colour mode.
4. Run the choreography. Named set pieces (`converge`, `zoom`, `wipe`) play only when moving forward; going back always uses the reversible depth `push`.
5. Call `scene.enter({ el, scope, dir, from })` with a fresh scope.

**Scene state vs DOM effects.** Every scene keeps a plain `state` object (selected persona, journey step and branch, dashboard tab and filter, simulator inputs). The DOM is always **re-rendered from state**; state is never read back from the DOM. For example, the use-case project card is *derived* from `(step, branch)` rather than accumulated, so going back always shows the correct numbers.

**Client-side calculations (`models.js`)** — no DOM, fully testable in Node:
- `delivery / riskGov / finance(filter)` compute all 18 dashboard KPIs for any project selection. Portfolio progress is budget-weighted; risk exposure is probability × impact, with ≥15 counted as high.
- `simulate({portfolio, projects, reduction, rollout})`:
  - annual benefit = portfolio × 11% baseline overrun × reduction%, plus projects × 3.5 h × 70% automated × 46 weeks × AED 210/h;
  - investment = AED 0.62M + AED 6K per project (×1.18 for big bang);
  - a monthly adoption ramp (6 months phased / 2 months big bang, with 12% first-year friction for big bang) produces the 36-month cumulative cash curve, payback month and ROI.

  The assumptions are printed on screen under *Show model assumptions*.

**Offline packaging.** One self-contained `index.html` (built by `build.py`), so it works even when opened from inside the ZIP. Classic `<script>` blocks (not ES modules, which Chrome blocks under `file://`), no `fetch`, no CDN, fonts embedded as base64 woff2, all visuals generated as SVG/canvas at runtime. Inactive scenes are `display:none`, and a loader waits for fonts so kinetic text is split with final metrics (no pop-in).

**Reliability.** 1920×1080 fixed stage, pinned by its centre and uniformly scaled/letterboxed; measured centred and fully visible at 1024×768, 1280×720, 1280×1024, 1366×768, 1440×900, 1536×864 and 1920×1080. Tested headless from `file://` with the network disabled at both resolutions: all scenes and interactions run with **zero console errors**, including a 25-keypress rapid-navigation stress test.

## Modifying live (examples)

- Change a project's forecast: edit `eac` in `src/js/data.js` and run `python build.py`. The dashboard, problem counters, constellation colours, module metrics and PowerPoint all follow.
- Change a business-case assumption: edit `ASSUMPTIONS` in `src/js/models.js`.
- Add a scene: add a `<section class="scene" id="s-x" data-title="…">` and push an object `{ id:'s-x', layout:['ring','healthy'], enter(ctx){…} }` into the array in `src/js/scenes.js`. The HUD and keys pick it up automatically.
